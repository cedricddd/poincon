POINTS CRITIQUES DU SYSTÈME
================================================================================

🚨 **Multi-tenancy security (DATA LEAK RISK)** :
   → TOUTES les routes /api/admin/* DOIVENT filter by company (companyId)
   → Actuellement CASSÉ: /api/admin/requests, /api/admin/approve
   → À vérifier: presence, sites, users/anonymize, rtt, time-off, schedules
   → Pattern: const { companyId } = await requireAdminWithCompany()
   →         WHERE { user: { companyId } } ou WHERE { companyId }
   → Test: Admin A cannot read/write/delete data from company B

⚠️ **Prisma + Docker** : JAMAIS `migrate dev` (shadow DB incompatible)
   → Toujours : `db push --skip-generate && prisma generate` + recreate container

⚠️ **Env vars Docker** : Lire `.env` (PAS `.env.local`)
   → Après changement `.env` → `docker-compose up -d app` (pas restart)

⚠️ **Port DB Windows** : 5433 externe (5432 pris par Veeam)
   → Interne Docker : db:5432

⚠️ **Stripe webhooks dev** :
   → stripe listen --api-key sk_test_... --forward-to http://localhost:3000/api/stripe/webhook

⚠️ **Roles hierarchy** : SUPER_ADMIN > ADMIN > MANAGER > EMPLOYEE
   → SUPER_ADMIN peut override tout + gérer plans + voir toutes companies
   → ADMIN gère UNE company (accès tous les employés + data de sa company)
   → MANAGER gère son équipe seulement (sa company seulement)
   → EMPLOYEE accède son dashboard personnel seulement
