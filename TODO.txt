PHASE 11: HEURES SUPPLÉMENTAIRES — MODE PRÉ-AUTORISATION (À FAIRE PLUS TARD)
================================================================================

Contexte : aujourd'hui DetectedOvertime fonctionne en a posteriori
(détection au pointage départ + approbation après coup).
Nouveau besoin : autorisation a priori pour cadrer les HS avant qu'elles
arrivent (anti-abus, conformité légale BE).

[ ] Modèle OvertimeAuthorization
    [ ] userId, date, maxHours, reason, status (PENDING/APPROVED/REJECTED)
    [ ] approverId, approvedAt, rejectionReason
[ ] Flow employé : demande "le 15/05 j'autorise jusqu'à 3h sup"
[ ] Flow manager : approbation depuis /manager/dashboard
[ ] Côté pointage : check au clockOut
    [ ] Si dépassement ET autorisation valide → accepté silencieusement
    [ ] Si dépassement SANS autorisation → bloque OU marque unauthorized
[ ] Choix mode par entreprise/employé :
    [ ] Mode souple (DetectedOvertime existant)
    [ ] Mode strict (OvertimeAuthorization obligatoire)
    [ ] Mode mixte (autorisation optionnelle, sinon détection auto)
[ ] Page /app/overtime → ajouter onglet "Demander autorisation"
[ ] Page /manager/dashboard/overtime → file d'attente autorisations
